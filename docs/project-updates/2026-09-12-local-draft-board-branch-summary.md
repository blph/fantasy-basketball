## In one paragraph

The board now exists twice: the Google Sheet a person drafts from, and a local JSON snapshot
with a Python mirror of the sheet's draft-day formulas that an agent reads and ticks through
`board.py`. One `build_data.py` run writes both. They are kept in step by applying the same
change to both, never by pulling one from the other, and `verify.py --local` holds the engine
to the live sheet.

## Why

| Owner requirement | Met by |
|---|---|
| A format built for agents, not people | Compact JSON snapshot, read only through `board.py` |
| Never committed or pushed | Lives under gitignored `data/draft-board/`; `check-no-data.sh` blocks it anywhere; AGENTS.md boundary |
| The sheet's live calculations run locally | `board_engine.py` |
| Kept in sync by applying the same change to both | One build writes both; `verify.py --local` checks the live sheet; AGENTS.md change-both rule |
| Faster for an agent than Playwright | One local CLI call per question, compact output |
| Every dependent accounted for | Export, mock-draft guard, docs, CI, agents file |

## Update, 2026-09-13: fast pull and a scripted tick scenario

- **`pull_sheet.py` downloads the workbook as one xlsx** through the owner's browser instead
  of ~94 gviz requests: about 3 seconds instead of 1.5 minutes. xlsx stores numbers to 10
  significant digits, so a pull records `sig_digits: 10` and `verify.py --local` compares at
  that precision; full-precision pulls still compare to 1e-9. The last gviz pull and an xlsx
  pull of the live sheet agreed on every cell the ticks do not drive.
- **`tick_scenario.py` runs the whole tick scenario as one command** on a throwaway copy:
  inherited ticks cleared, MINE 8 then 14, GONE on 10, one then two punted categories, a new
  sort with Rebuild & re-sort (the copy's authorisation, allowed with the owner's approval),
  and a reordering Refresh with a hand value and two swapped names on clean rows. Every step
  passed `verify.py --local` in full (exit 0), the hand value stayed on its row, and the copy
  was deleted permanently and confirmed gone. That pass closes C1 in the sheet. One run takes
  about 8.5 minutes of wall-clock and a single line per step of output. (That hand value sat on
  a row the swap never moved, so it did not prove re-attachment by name; see 2026-09-14.)
- Found on the live sheet: the Board's `My GP` (W) and `XRank` (Z) columns are hidden, so the
  Name Box cannot reach them; the scenario's hand value goes in `GP Y-1`. The live sheet also
  showed 0 MINE ticks where the 03:33 pull had 7; the owner chose to leave them unticked.
- Six earlier attempts each left a test copy behind; every one was found by id, confirmed by
  its contents, and permanently deleted. The older, unstamped copy in the owner's Drive was not
  touched.

## Update, 2026-09-14: the tick scenario checks what it claimed to

A code review of the scenario found three steps that could pass without testing their point.
Fixed in `tick_scenario.py`, with tests, and the scenario passed on a copy (every step at
verify exit 0, copy deleted, 320 s):

- **Step e** types the hand value on one of the two swapped rows. Refresh keys hand values by
  the name a row shows, so the value must land on the swapped-in player's new row and be gone
  from the row it was typed on. A refresh keeping hand values by row position now fails.
  Re-attachment by name is verified in the sheet.
- **Step d** fails unless Settings `SORT_BY` reads the new sort and verify sees the board
  sorted by it. `onEdit` swallows its own errors, so a sort that never landed used to pass.
- **The copy** is recorded for deletion as soon as it has an id, so a timeout or a failed title
  check after it exists no longer leaves it in Drive silently.
- Not fixed: the "scenario not needed" gate records the repo's HEAD, not what `Code.gs` the
  sheet runs, so a change tested before deployment can later be skipped. Run it with `--force`
  after a deploy until that gate compares against the deployed script.

## Update, 2026-09-18: Compare picks, and CMP replaces GONE

- **Compare picks** (ADR-0027) sits beside the Category Tracker. It has up to five candidate
  columns, and each is the tracker as it would read with that player ticked MINE. Candidates
  rank on expected categories won, the sum of Win % over the categories not punted. A glyph
  marks a category whose Read would change, and "vs best" gives each one's gap to the top
  candidate. The engine mirrors it in `board_engine.compare`, and `board.py compare NAME…`
  answers the same question locally. A test holds each column equal to `tracker()` with that
  player ticked.
- **CMP replaces GONE** (ADR-0028). The owner never ticked GONE, so the column became `CMP`:
  tick it beside the players you are deciding between, and they fill Compare picks, best board
  # first, with MINE left out. Past five, the panel compares the best five and says so. Every
  CMP tick clears three ways: the **Clear all** box beside the panel title, any **MINE** tick
  (both through the simple `onEdit`), or **Draft Board ▸ Clear compare**. `Left @pos` left the
  sheet with GONE. `board.py gone` stays as the agent's local pick log. A rebuild never reads an
  old GONE tick as CMP, and the build removes the retired `DB_GONE` named range.
- **Deployed and verified in the sheet** after each change: Code.gs replaced through Monaco,
  then a Full rebuild, then a pull, then `verify.py --local` at exit 0.
  - The live check ticked 3 MINE and 6 CMP. Verify passed at n = 3, and the note read
    "Top 5 of 6".
  - The Clear all box cleared 6 ticks and reset itself.
  - A MINE tick cleared 2.
  - The sheet was restored to zero ticks, and it passes verify at zero.
- **Found in the sheet and fixed:**
  - the panel's `3PM` label was being read as 3:00 PM (the labels are now plain text, and
    verify checks them);
  - long names clipped at both ends (the slots are now left-aligned).
- **Seen and recorded, not fixed:** the MINE auto-clear lands a second or two after the tick, so
  a CMP tick made in that window is cleared too (ADR-0028).
- **Not run:** the tick scenario. Its gate asks for the full tier, which needs consent on the
  copy's authorisation screen, and the owner deferred it. Its new steps f and g prove both clear
  routes on a copy; until it passes, the rebuild path with CMP is proven only by the live Full
  rebuilds above.

## Update, 2026-10-11: one GP, Basketball Monster's comments, collapsing projections

- **The Draft Board changed shape** (ADR-0030).
  - One `GP` column replaces `Proj GP`, `My GP` and `Flag`. It carries BMP's projected games,
    which were not in `Data.gs` before: every calculation tab holds Hashtag's raw line.
  - `Notes` shows Basketball Monster's comment on each player. Type over a cell and the note
    is yours; a re-sort carries only typed-over cells.
  - Each projection's six columns are a column group, collapsed after every build and re-sort,
    with a narrow label column ahead of it. The row-1 checkboxes and `Apply projection filter`
    are gone.
  - The TIERING block moved into the hidden helpers. `TIER` and the tier lines are unchanged.
- **The data moved to the 2026-10-11 exports.** Comments are an optional seventh file in the
  dated set. The snapshot is schema 2, with `bmp_gp` and `comment` on every player.
- **Deployed and verified in the sheet.** `Code.gs` and `Data.gs` were replaced through Monaco
  and their hashes read back after a reload. A Full rebuild ran in 173 seconds. A pull of the
  result passed `verify.py --local` at exit 0 on all 200 rows.
- **The tick scenario passed at the full tier**, 266 seconds, every step at verify exit 0, the
  copy deleted. The owner approved the consent screen. This also closes the "Not run" item in
  the 2026-09-18 update.
- **One known data gap.** `verify.py --published` fails its worst-row gate on one board row in

  error is inside its gate on both sources. A fresh export of the two vendor files clears it.
- **No longer checked:** the Draft Board does not mirror `My GP`, so `verify.py --local` cannot
