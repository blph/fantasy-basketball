# ADR-0008: A Google Sheet draft board, fed by manual exports, for the 2026-27 draft

- Status: Accepted
- Date: 2026-08-27
- Owner: Bryan

## Context

The 2026-27 draft arrives before the pipeline does. Phase 2 ingestion does not
exist — there is no database, no valuation code, and the ESPN and Yahoo
integrations chosen in [ADR-0007](ADR-0007-espn-primary-data-source.md) are not
built. The draft assistant described in Phase 3 of the
[roadmap](../roadmap.md) is further out still.

Meanwhile the valuation method is fully specified. The
[draft playbook](../references/fantasy-basketball-draft-playbook.md) sets out
z-scores on a fixed pool, G-score multipliers for week-to-week variance, VOR,
a games-played adjustment, tier cutting, and punt re-ranking. What is missing is
an implementation, not a design.

A projections subscription was considered and declined for this season, which
leaves manual exports as the input.

## Decision

Build the board as a **Google Sheet**, generated by a Google Apps Script in
`scripts/draft-board/`, fed by **manual Hashtag Basketball exports** dropped into
gitignored `data/player_data/`.

Every value a player is judged on is a **live formula referencing named ranges**,
not a number computed in the script and pasted in. The constants — pool size,
the nine G-score multipliers, the tier threshold, the games-played divisor —
live on a Settings tab as named ranges, so the model can be retuned without
touching code.

## Consequences

**Good.** It exists in time for the draft. The math is auditable cell by cell,
which matters more than elegance when a pick is on a 60-second clock. Retuning a
constant recalculates the whole board. The output was verified against an
independent Python implementation of the same playbook: all 200 rows agree on Z
and G totals, and all eight pool constants agree to four decimal places.

**Bad.** It is a second implementation of a valuation that Phase 2 will have to
implement again in Python. That duplication is accepted deliberately: the
spreadsheet is disposable, and the playbook — not either implementation — is the
specification.

**Provider data.** The exports are Hashtag Basketball's and stay in gitignored
`data/`. The generated `Data.gs` is gitignored too, since it would otherwise sit
committable inside `scripts/`. `Build.gs` holds formulas and formatting only and
contains no player data. This is consistent with
[ADR-0006](ADR-0006-no-provider-data-redistribution.md); the test harness
synthesizes its own players so it runs on a clean clone.

**Not a reversal of ADR-0007.** ESPN and Yahoo remain the pipeline's data
sources. This is interim tooling for one draft, not a change of provider.

New exports are brought in by a `Refresh data` action that writes only the
cells whose values changed and preserves the hand-edited columns, so the
games-played overrides that section 6a asks for survive every import. The
operating manual is [docs/draft-board/](../draft-board/build-and-maintenance.md).

## Deliberate deviations from the playbook

Recorded because they are judgment calls, not oversights:

- **Tier multiplier defaults to 4.0, not 2.** Section 7a targets 12 to 15 tiers
  across 200 players and offers 2 as a starting point. On this data 2 produces
  46 tiers, which is unusable; 4.0 produces 14. The playbook calls the 2 "a
  starting point, not a law", and this is the calibration it invites.
- **Gap is computed against Adj Rank, not the VOR rank.** Section 6 derives My
  Rank from VOR, but section 7 sorts the board by Adjusted Value. Adjusted Value
  is what you actually draft from, so it is the rank the market comparison
  should run against. Both rank columns exist on the Board.
- **The category tracker is automated** from checkboxes rather than typed in
  after each pick, as section 6 describes.
- **Pool iteration is a menu action**, not Sheets iterative calculation. Pool
  membership keys off a static Seed Rank to avoid a circular reference; running
  the action once performs one iteration of the playbook's convergence step.

## Known limitation

The ADP in the current export is Hashtag's, not confirmed Yahoo. Section 2 of
the playbook is explicit that ADP is platform-specific and that Yahoo's is the
one that matters, because that is the room being drafted in. The XRank column
exists and is empty. Worth replacing before draft day if the data can be got.
